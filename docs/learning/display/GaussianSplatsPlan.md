# Native Gaussian splats implementation plan

Implement an opt-in preview in iTwin.js's WebGL2 renderer. Load Gaussian splats through the existing reality-model and 3D Tiles pipeline, preserving compatibility with CesiumJS and Cesium ion data without using Cesium's renderer.

## Compatibility and scope

- Accept glTF 2.0 `KHR_gaussian_splatting` and the draft nested `KHR_gaussian_splatting_compression_spz_2` used by Cesium. Reject the removed original SPZ extension.
- Support explicit 3D Tiles trees, single GLB/glTF content per tile, and nested external tilesets. Diagnose implicit tiling and multiple contents. Standalone PLY/SPZ, reconstruction, upload, export, and tiling are deferred.
- Decode linear scales, normalized opacity, xyzw quaternions, and complete spherical harmonics through degree 3. Apply SPZ scale/opacity activations only to compressed data. Standards-based compressed content decodes in glTF's LUF coordinate system; the established Cesium draft profile preserves its stored convention.
- Support perspective and orthographic 3D views, view/branch clipping, opaque BIM occlusion, and model picking. Picking uses the nearest mean-plane fragment with Gaussian alpha at least 0.1; splats supply no measurement or snapping geometry.
- Blend in the declared trained color space before converting linear colors to display colors. Correct interleaving with translucent BIM and mixing differently trained color spaces are preview limitations.

## Implementation

1. Add `RenderSystem.Options.enableGaussianSplats` (`@alpha`, default false), internal splat data/geometry, and Display Test App configuration.
2. Add validated raw accessors and SPZ decoding in a bundled browser worker. Resolve external buffers through the reality data source so ion authentication follows the existing transport. Reject malformed or unsupported profiles with diagnostics.
3. Add a dedicated Gaussian render pass. Gather visible tiles across each viewport, retain high precision transforms relative to tile origins, globally radix-sort off the main thread, and draw projected covariance ellipses with spherical harmonics. Share paged GPU storage across viewports; release data as tile geometry expires and include allocations in memory accounting.
4. Integrate resolved opaque depth, logarithmic depth, clipping, and native pick attachments. Preserve the renderer's cached GL state. Coalesce camera updates and reject sort results for stale content generations.
5. Add offline decode and rendering fixtures, worker/lifetime tests, and a reproducible 1-million/4-million visible-splat benchmark. Compare a compatible live ion asset with CesiumJS 1.146 when credentials and hardware permit.
6. Build, test, lint, run Rush dependency/API checks, review generated API reports, add a Rush change file, and validate release notes. Do not push or create a PR.
7. Use Display Test App's existing Models picker, Diagnostics window, and Inspect Element tool with a real read-only iModel. Attach Gaussian content through the existing reality-model tools and capture evidence; a blank connection or exported mesh alone does not satisfy this demonstration. Use existing viewport cloning/docking for campus overview and BIM detail views, with a demo copy of the iModel placed inside the real capture.

For live captures, evaluate persistent visible patches against settled captures at the same camera poses, accounting for camera motion, clipping, BIM/terrain occlusion, and LOD differences. Abrupt coverage loss or a one-frame brightness excursion should save a suspect window; raw adjacent-image differences are not an automatic failure rule. 5. **Validate the detector:** intentionally suppress one Gaussian draw, reset blending to source order, and discard the completed selection before delivering its replacement in test-only fault runs. The detector must catch each known failure. Negative controls include valid clipping, model removal, camera motion, and legitimate detail changes; these must not be mislabeled as missing-field flashes. 6. **Separate visual and timing runs:** capture reduced-resolution framebuffer evidence after every draw in a dedicated visual pass; retain a bounded ring of frames and save the frames before/during/after failures plus JSON telemetry and a contact sheet or short animation. GPU fences/readbacks establish completion for that pass. Full framebuffer readbacks and `gl.finish()` can perturb worker scheduling and stall the GPU, so measure responsiveness in a separate matching route with inexpensive counters, animation-frame intervals, input-to-next-frame delay, long tasks, and p95/p99 frame gaps. Use the same route/configuration and report the instrumentation difference. Calibrate timing limits on named hardware; avoid a universal FPS score.
7. **Gate continuity, fidelity, and responsiveness separately:** correctness must pass the known-visible-region and fault-detector assertions. Fidelity must demonstrate expected refinement at dwell poses and acceptable settled reference patches; staying permanently coarse or retaining an old completed field indefinitely must fail this gate even when it avoids flashes. Responsiveness reports raw timing/long-task data against the recorded hardware baseline. Report unknown or missing measurements as unverified. Check peak transition overlap and return to the expected quiescent resource baseline after repeated routes or viewport disposal. Save replayable seeds, sanitized configuration/content identity, raw samples, and failure artifacts rather than only a green result.

Implement the offline route and detector positive/negative controls first, then add the opt-in live DTA integration and timing route. This keeps the CI gate independent of ion availability while adding evidence for the real navigation experience.

The routine command is `rushx test GaussianSplatsValidation.test.mts` from `core/frontend`; `ITWIN_GAUSSIAN_VALIDATION=1` additionally saves JSON and standalone contact sheets under `lib/gaussian-validation-*.{json,html}`. In DTA, `dta gaussian trace visual [output-prefix] [cold|warm|unknown]` captures visual evidence, `dta gaussian trace timing ...` omits GPU readbacks, and `dta gaussian trace stop` saves both artifacts. `dta gaussian trace replay <trace.json>` replays saved frustum poses at their recorded timestamps while either recorder is active. Programmatic replay supplies no wheel-input latency measurement; actual wheel/pointer runs remain separate. Recordings stop after 60 seconds in DTA, retain failed saves for retry, and detach native observers/timing callbacks on disposal. The core recorder also stops after 180 seconds or 3,600 native frames.

## Design findings during implementation

- **Dedicated blending pass:** iTwin.js's ordinary transparent pass uses weighted order-independent transparency. Gaussian splats require sorted alpha composition; they must render after opaque BIM in a separate pass and before ordinary translucency.
- **Shared GPU storage:** sorting independently within tiles produces overlap seams. A viewport-wide instance list can reference shared paged splat storage while carrying per-tile transforms, clip planes, and feature IDs. This also avoids duplicating splat textures across viewports.
- **Worker packaging:** the existing frontend worker build produces a self-contained classic script in `public/scripts`. The splat worker will use the same packaging and public-path conventions.
- **WASM worker URL:** the SPZ Emscripten glue uses `import.meta.url`. The classic-script build must replace it with `self.location.href`; Rollup's default IIFE replacement references `document.currentScript`, which fails in a worker. Golden decode tests caught this.
- **SPZ adapter:** `@spz-loader/core@0.3.1` already exponentiates scales and applies sigmoid to alpha. Request a DC color factor of 1, remove its 0.5 offset to recover SH coefficients, and apply no further scale/opacity activation. Validate this against a compressed golden fixture. Decode explicitly in LUF.
- **SPZ antialias flag:** preserve the decoder's training flag. Apply projected covariance determinant compensation when broadening antialiased splats with the pixel filter, rather than silently treating them as conventional splats.
- **Affine covariance and SH:** transform covariance with the full model-view linear transform. Evaluate SH using the camera-to-mean direction expressed in the original local coordinate system; this preserves directional lighting under node/tile rotations without rewriting SH coefficients.
- **Dependency setup blocker:** the first `rush update` reached an unrelated backend native postinstall and failed with registry authentication error E401. Frontend work continues with lifecycle scripts skipped; the full repository build may still need those credentials. This does not change the renderer architecture.
- The user refreshed VSTS authentication; retry the normal Rush installation before verification.
- **Dependency setup resolved:** normal `rush update --recheck` passed after the authentication refresh. `rush build --to @itwin/core-frontend` also passed for all 13 selected packages.
- **LOD readiness:** decoded content is committed only after the decode worker finishes. Retain one completed global field while the latest candidate selection awaits both native visible coverage and its sorting worker, then hand off the whole selection atomically. New multi-splat content becomes visible and pickable only after its global order is ready; a single splat has no ordering ambiguity. Initial content still needs its first sort and can build up progressively before the first complete source selection. This prevents a missing field during replacement sorting or partial reload; it does not crossfade changes in capture detail.
- **Residency:** share GPU pages selected or retained by at least one viewport. Charge cached tile CPU data and worst-case GPU page size to the existing tile-cache budget; separately account for completed-field geometry retained through a transition. One completed selection and one latest candidate can coexist in CPU, worker, and GPU storage. Tile-cache eviction does not dispose the completed field until its renderer leases are released. The atlas is capped by the device's array texture layer limit; exceeding it reports a diagnostic. An active source can retain its completed field through a temporary empty native selection; this is not an automatic active-splat budget.
- **Viewport state:** the native renderer shares one canvas across viewports. The dedicated pass sets and restores the GL viewport explicitly; framebuffer binding alone does not select the target's dimensions. Browser fixtures read the actual viewport center because frontend initialization can resize their container.

Absolute ion resources receive asset authorization only inside the endpoint's origin and path.
- **Multisampling:** custom draws bypass the native technique executor's dirty-buffer tracking. Mark the composite destination dirty and resolve its MS color attachment after the Gaussian pass; resolve opaque MS depth before testing Gaussian fragments.
- **Cesium SPZ convention:** CesiumJS 1.146's loader uses `UNSPECIFIED`, while the Khronos SPZ draft requires LUF. Live BIM/map foreground cannot substitute for a splat-only pixel oracle. Save live frames/configuration and mark that stronger result unverified. Packed-memory telemetry measures arrays leased by the viewport, including current/completed fields, and excludes worker scratch and GPU buffers. DTA reuses its existing local file RPC to replay numeric native frustums, keeping iModel trees and source selection live; skipped poses under lag are reflected in the newly recorded actual camera, and replay is distinct from physical input latency. No new RPC signature or viewer panel is needed.
- **Replay and recording lifetime:** reserve a replay operation before awaiting its file read, reject duplicate starts, and cancel it on stop or viewport disposal even when no recorder is active. Validate root/frame shapes, monotonic finite timestamps, and explicit x/y/z coordinates before applying frustums; reject malformed input with cleanup. Save callbacks retain the stopped recorder until both JSON and HTML writes succeed. Diagnostic callback exceptions cannot abort native rendering, and an old unsubscribe callback cannot remove a newer observer set. Bound failure evidence separately from ordinary milestones and preserve the frames after a failed readback even when that frame has no image.
